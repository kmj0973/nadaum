# 배포 1년 후 보안 리뷰 — 인증 구조 결함 발견과 수정

> 2026-09-06 · 배포(2025.06) 약 1년 후, 코드를 다시 열어 인증 구조를 점검한 기록.
> AI 코딩 에이전트(Claude Code)로 전체 코드 흐름을 리뷰시켜 후보를 찾고, 각 항목을 코드에서 직접 재확인한 뒤 수정했다.

## 발견한 문제

### 1. 토큰을 아무도 검증하지 않았다 (심각도: 높음)

- `middleware.ts`는 `token` 쿠키의 **존재 여부만** 확인했다. `document.cookie = "token=aaa"` 한 줄이면 로그인 없이 보호 페이지에 접근 가능했다.
- `/api/login`은 클라이언트가 보낸 토큰을 검증 없이 그대로 쿠키에 담았다.
- 부가 결함: Firebase ID 토큰의 수명은 1시간인데 쿠키 maxAge는 24시간 — 검증을 추가하더라도 1시간 뒤부터는 만료 토큰이 담긴 쿠키가 돌아다니는 구조였다.

### 2. `/api/chat`이 무방비였다 (심각도: 높음 — 비용 직결)

미들웨어는 페이지 라우팅만 막고 API 요청은 막지 않는다. OpenAI 토큰이 소모되는
엔드포인트를 누구나 직접 호출할 수 있었다. 대화 이력 전체를 매 요청에 실어 보내
비용이 대화 길이에 비례해 무한정 커지는 문제도 함께 있었다.

### 3. 신뢰할 수 없는 입력을 신뢰했다

- 회원가입 직후 신체정보 입력 폼이 **URL 쿼리의 uid**(`/signup/info?uid=...`)로 Firestore에 쓰기를 시도했다. URL만 바꾸면 다른 계정 문서 경로로 쓰기를 시도할 수 있다.
- 로그아웃이 쿠키·전역 스토어만 지우고 `signOut()`을 호출하지 않아 Firebase 세션이 브라우저(IndexedDB)에 남았다.

### 4. 동작 버그 (보안 외, 함께 수정)

- 채팅 저장 시 사용자 질문이 **빈 문자열로 저장** — `useChat`이 제출 즉시 input을 비우는데, 응답 완료 시점(`onFinish`)의 input을 저장하고 있었다
- 나이 계산·검증에 연도(2025) 하드코딩 — 해가 바뀌면 1살씩 틀린다
- `if (docSnap.data)` — 메서드 참조라 항상 참. `docSnap.exists()`가 맞다

## 수정 내용

| 문제 | 수정 |
|---|---|
| 토큰 미검증 | `firebase-admin` 도입. `/api/login`에서 `verifyIdToken()` 후 **세션 쿠키**(`createSessionCookie`, 24h)로 교환 — 수명 불일치도 함께 해결 |
| `/api/chat` 무방비 | `verifySessionCookie(session, true)` 검증, 실패 시 401. 대화는 최근 20개만 전달 |
| URL 쿼리 uid | 로그인 세션(스토어)의 uid만 사용하도록 변경 |
| 로그아웃 불완전 | `signOut(auth)` 추가 |
| 동작 버그 3건 | 제출 시점 input을 ref로 보관, `getFullYear()` 사용, `exists()` 사용 |

### 설계 노트: 왜 미들웨어에서 검증하지 않았나

Next.js 미들웨어는 Edge 런타임이라 `firebase-admin`(Node 전용)을 쓸 수 없다.
계층을 나눴다: **미들웨어는 UX 레이어**(비로그인 리다이렉트 — 쿠키 존재 확인으로 충분),
**실제 보안 경계는 비용·데이터가 걸린 서버 핸들러**(`/api/chat`, `/api/login`)에서
세션 쿠키를 검증한다. Firestore 직접 접근은 보안 규칙(`request.auth.uid == userId`)이 경계다.

## 배포 전 필요한 설정

1. Firebase 콘솔 → 프로젝트 설정 → **서비스 계정** → "새 비공개 키 생성"
2. 받은 JSON 전체를 한 줄로 만들어 환경변수로 등록 (로컬 `.env` + Vercel):
   ```
   FIREBASE_SERVICE_ACCOUNT_KEY={"type":"service_account","project_id":"...", ...}
   ```
   ⚠️ `NEXT_PUBLIC_` 접두사 절대 금지 (클라이언트 번들에 노출됨)
3. 배포 후 확인: 로그인 → 챗봇 정상 동작 / 쿠키 삭제 상태에서 `/api/chat` 직접 호출 시 401
